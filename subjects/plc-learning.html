● Basic

What Is a PLC

Hardware

A Programmable Logic Controller is an industrial computer built to read inputs, execute a stored program, and drive outputs — continuously, deterministically, and reliably enough to run unattended machinery for years. It replaced cabinets of individual relays wired together: the same start/stop/interlock logic that once took a wall of physical relays and miles of wire now lives as a program, re-wireable in software instead of with a screwdriver.

PLC Hardware Architecture

Hardware

A PLC system is built from a handful of standard pieces, whether it's one compact brick or a rack of modules:

ComponentJob
CPU / processorstores and executes the program, holds the memory image of all I/O
Power supplyconverts mains or 24VDC input into the regulated rail the rack's electronics need
Digital input modulereads ON/OFF field signals — switches, push-buttons, proximity sensors
Digital output moduledrives ON/OFF field devices — relays, solenoids, indicator lamps
Analog input modulereads continuous signals — 4–20mA transmitters, 0–10V sensors
Analog output moduledrives continuous actuators — a control valve's positioner, a VFD speed reference
Communication moduletalks to other devices — Modbus, Ethernet/IP, Profibus/Profinet

Most modern small-to-mid PLCs integrate the CPU, power supply, and a base set of digital I/O into one compact unit, with expansion modules added as needed — the modular rack style is more common in larger installations.

Typical industrial digital I/O runs at 24VDC. Wiring diagrams always specify which convention a module expects — check the sensor's own label (PNP/NPN, or "sourcing/sinking") against the module's datasheet before powering up.

Analog I/O Basics

Hardware

Where digital I/O is simply ON or OFF, analog I/O carries a continuous value — most commonly a 4–20mA current loop (see the Electronics & Instrumentation tutorial's current loop section for why current, and why 4mA rather than 0mA, were chosen) or a 0–10V signal. Inside the PLC, the analog module's ADC turns that signal into a raw integer — the program then scales that raw integer into an engineering value the rest of the logic can use. The Analog Input Scaling Calculator above does exactly that conversion.

Ladder Logic Fundamentals

Programming

Ladder logic is drawn as a series of horizontal "rungs" between two vertical power rails, deliberately modelled on the relay wiring diagrams it replaced:

A simple rung: Start contact AND NOT Stop contact energizes Motor
| Start Stop Motor |
  • Contact (−| |−): a normally-open (NO) contact, true when its associated bit is 1.
  • Contact (−|/|−): a normally-closed (NC) contact, true when its associated bit is 0 — marked with a × above.
  • Coil (−( )−): the rung's output; energized when every contact in the path from left rail to coil is true (power can "flow" through).

Contacts in series (one after another) behave as AND; contacts in parallel branches behave as OR — precisely the series/parallel logic from the Electronics & Instrumentation tutorial, here used to combine true/false conditions instead of currents.

Memory & Data Types

Programming

A PLC's memory is organized in a few standard sizes, and every I/O point and internal flag lives at an address within it:

TypeSizeTypical use
Bit / Bool1 bita single input, output, or internal flag — ON/OFF
Byte8 bitsrarely addressed directly; a building block for larger types
Word / Int16 bitsa raw analog reading, a counter value, a small integer
DWord / DInt32 bitsa larger counter, a timer accumulator in milliseconds
Real / Float32 bitsa scaled engineering value (50.25°C, 3.14 bar)

Addressing conventions vary by vendor (Allen-Bradley's tag-based naming, Siemens' I0.0 / Q0.0 / M0.0 byte.bit style, and others) but the underlying bit/word/dword structure is universal.

Programming Software Workflow

Programming

Regardless of vendor, the development cycle follows the same shape: write the program offline, download it to the PLC, go online to monitor live contact/coil states overlaid on the ladder as the machine runs, make edits (many platforms support online editing on a running machine, with appropriate caution), and upload from the PLC if you ever need to recover the program from a machine whose only copy lives in its memory.

Always keep an offline copy A PLC with no backed-up program file, only the program resident in its memory, is one battery failure or one accidental download-of-the-wrong-file away from a very bad day. Archive the program file after every change, labelled with a version and date.

Timers (TON/TOFF/RTO)

Programming

Three timer instructions cover almost everything:

InstructionBehaviour
TON (on-delay)output turns ON only after the input has been true continuously for the preset time; drops immediately when input goes false
TOFF / TOF (off-delay)output follows input ON immediately, but stays ON for the preset time after input goes false before dropping
RTO (retentive)like TON, but the accumulated time is not reset when the input drops — it keeps counting from where it left off next time input goes true, until explicitly reset

Worked example: TON preset = 3.0s, input stays true for 5.0s. Output turns ON at t = 3.0s, stays ON until the input drops at t = 5.0s — an ON duration of 2.0s. Try it in the calculator above, including the TOFF case.

Counters (CTU/CTD)

Programming

Where a timer counts elapsed time, a counter counts discrete events — each rising edge on its input increments (CTU, count-up) or decrements (CTD, count-down) an accumulator. When the accumulator reaches a preset, a "done" bit sets, exactly like a timer's done bit. CTUD combines both directions in one instruction, common for tracking a net quantity (parts into a buffer minus parts out).

A classic use: counting parts off a conveyor past a photoeye, triggering a downstream action (divert, batch-complete, reject) once a target count is reached — and persisting the count across a power cycle if the counter is configured as retentive.

Latching & Seal-In Circuits

Programming

A push-button is only pressed momentarily, but a motor needs to stay running after the button is released. The standard pattern — carried over directly from relay logic — is a seal-in (or "holding") contact: a copy of the output's own contact wired in parallel with the Start button, so once the coil energizes, it keeps its own rung true even after Start is released.

Start/Stop with seal-in: once Motor energizes, its own contact holds the rung true
| Start Stop Motor |
| Motor |

The Stop button is wired as normally-closed: pressing it breaks the circuit (rather than making a separate "stop" path), so the rung — and therefore the motor — also drops safely if the Stop button's wire is ever cut or disconnected. This "NC for stop/safety" convention is the single most important wiring habit in industrial control; it reappears directly in the Safety Interlocking section below.

Comparison & Math Instructions

Programming

Beyond simple bit logic, most programs need to compare and calculate values:

InstructionFunction
EQU / NEQequal / not equal
LES / GRTless than / greater than
ADD / SUBaddition / subtraction
MUL / DIVmultiplication / division
MOVcopy a value from one memory location to another — used constantly to move a scaled analog reading into a working register

These behave as rung-level conditions (a GRT instruction is true/false, feeding into the same AND/OR rung logic as a contact) or as actions executed when a rung's conditions are met — the exact mechanics vary by platform, but the pattern is universal.

Program Organization

Programming

Beyond a handful of rungs, programs are broken into a main routine that calls subroutines (grouped by machine function — conveyor control, recipe handling, alarm logic) and, on more structured platforms, reusable function blocks — a self-contained piece of logic (like a motor-start sequence) written once and instantiated for every motor that needs it, each instance with its own private data.

This mirrors ordinary software engineering: avoid one giant routine, group related logic, and extract anything repeated into a reusable block rather than copy-pasting rungs.

Motor Control Circuits

Hardware

The Start/Stop/seal-in pattern above is the foundation; real motor circuits add two further layers:

  • Interlocking: preventing two conflicting outputs from energizing together — e.g. a forward contactor and a reverse contactor must never both close at once (a direct electrical short across the motor supply). Each coil's rung includes the other coil's contact wired NC, so energizing one physically can't permit the other.
  • Overload protection: a motor overload relay's NC contact is wired into the same Stop-style series path as the Stop button itself, so an overcurrent trip drops the motor exactly the way pressing Stop would.

Forward/reverse motor control is the textbook example combining seal-in, interlocking, and overload protection in one circuit — worth studying as a complete pattern rather than three separate ideas.

Sequential Control & State Machines

Programming

Many machines don't run one flat set of rungs forever — they move through a sequence of distinct steps (fill → mix → heat → discharge), each with its own permitted outputs and its own condition for advancing to the next. The common pattern is a step/state register: an integer holding "which step we're in," with each step's logic gated by EQU(step, N), and a transition rung that advances the step number once that step's completion condition is met.

The IEC 61131-3 standard formalizes this as Sequential Function Chart (SFC), a dedicated graphical language of steps and transitions purpose-built for exactly this pattern — see Beyond Ladder below.

Analog Scaling & PID in PLCs

Programming

Closing a real control loop inside a PLC combines the Analog I/O and scaling covered above with the PID control theory from the Electronics & Instrumentation tutorial: read a scaled process value (PV) from an analog input, compare it to a setpoint (SP), run it through a PID instruction block (available as a built-in instruction on virtually every modern PLC platform) to compute an error-driven correction, and write that correction out through an analog output — a valve position, a VFD speed reference.

The PLC's job in this loop is almost entirely the "sense" and "scale" steps already covered; the PID math itself is usually a vendor-supplied instruction where you configure Kp/Ki/Kd and let the platform handle the calculation each scan.

Safety Interlocking & E-Stops

Hardware

Standard PLC I/O is not, by itself, safety-rated — a software bug or a stuck output could fail to stop a hazardous motion. True safety functions (emergency stops, light curtains, guard interlocks) are built on a separate principle: fail-safe wiring, where the safety circuit is wired NC and energized-to-run, so that any fault — a cut wire, a lost power supply, a tripped guard — removes power and the machine stops, rather than requiring a signal to actively command a stop.

Dedicated safety relays or safety-rated PLCs (with certified, redundant processing and monitored outputs) implement this to a certified standard (e.g. ISO 13849, IEC 62061) and are a legal requirement for machinery risk categories above the lowest tier — a standard PLC output driving an E-stop circuit, with no certified safety hardware, does not meet this bar on its own.

Never treat an E-stop as "just another input" E-stop and guard circuits should hard-wire directly into a safety relay or safety PLC that removes power at the contactor level — not merely set a bit that ordinary ladder logic then reacts to a scan later. The seal-in Stop button's NC convention is the same underlying idea, scaled up to a certified, hard-wired safety function.

PLC Communication: Modbus & Beyond

Programming

A PLC rarely works in isolation — it reads remote I/O, talks to an HMI, and reports to a SCADA system. The most widespread field protocol remains Modbus, covered in full in this Handbook's Modbus RTU/TCP tutorial: a PLC can act as a Modbus master, polling the exact kind of opto-isolated relay board and 4–20mA transmitters discussed in the Electronics & Instrumentation tutorial, or as a Modbus slave itself, exposing its own registers to a SCADA master.

Beyond Modbus, Ethernet-based industrial protocols (Ethernet/IP, Profinet) and older fieldbuses (Profibus, DeviceNet) serve the same basic need — moving I/O and diagnostic data between controllers, remote I/O racks, and drives — at higher speed and with richer diagnostics, at the cost of more complex configuration.

Fault Finding & Online Troubleshooting

Hardware

With the programming software online and monitoring, most faults fall into a short list of patterns:

  • Input never goes true: check the physical signal at the terminal first (meter, not software) — wiring, sourcing/sinking mismatch, or a failed field device are all more common than a logic error.
  • Output energizes in software but the field device doesn't move: the PLC's job ends at the output terminal — check the output module's own status LED, fuses, and the field wiring/contactor beyond it.
  • Logic looks right but never executes: check scan-level basics — is the routine actually called from the main program, is the PLC in RUN mode, is a higher-priority fault forcing outputs off.

Most platforms also allow forcing an I/O point to a fixed state for testing — invaluable for isolating whether a problem is in the field wiring or the program, but dangerous to leave forced on a production machine, since forced I/O silently overrides both the real field signal and the program's own logic.

SCADA & HMI Integration

Programming

An HMI (Human-Machine Interface) gives an operator screens, buttons, and indicators wired to PLC tags — the same memory addresses the ladder program reads and writes. A SCADA (Supervisory Control and Data Acquisition) system sits a level above, typically polling many PLCs across a site, logging trends to a historian, and raising alarms when a value leaves its configured limits.

Both layers depend entirely on the PLC's own data being well-organized and well-named — a program whose only interface is cryptic raw addresses makes both HMI screens and SCADA configuration far harder to build and maintain than one with clearly tagged, scaled engineering values ready to expose.

Beyond Ladder: IEC 61131-3

Programming

Ladder Diagram (LD) is one of five programming languages standardized by IEC 61131-3 for industrial controllers:

LanguageBest suited to
Ladder Diagram (LD)bit logic, interlocking — reads naturally to anyone trained on relay schematics
Function Block Diagram (FBD)signal-flow style logic — wiring blocks (timers, math, PID) together, common in process control
Structured Text (ST)a Pascal-like text language — far more natural for complex math, loops, and string handling than ladder
Sequential Function Chart (SFC)step-by-step sequencing, exactly the pattern covered above
Instruction List (IL)a low-level assembly-like language, largely deprecated in modern platforms

Most modern platforms let a program mix languages — ladder for the interlocking and start/stop logic, structured text for a calculation-heavy recipe routine, SFC for the overall sequence — using whichever language fits each piece of logic best rather than forcing everything into one.

● Practice Exercises
Basic Calculate total scan time and max reaction rate

A PLC's I/O scan takes 2ms, program execution takes 5ms, and comms/housekeeping overhead takes 1ms. What's the total scan time, and what's the fastest rate (in Hz) the PLC can possibly detect a changing input?

Answer Total scan time = 2 + 5 + 1 = 8ms. Maximum reaction rate = 1000/8 = 125Hz — an input pulse shorter than one scan (here, under 8ms) risks being missed entirely.
Basic Match sensor type to input module type

A proximity sensor is labelled "PNP" (sourcing). What kind of PLC digital input module does it need to be wired to?

Answer A sinking input module. A PNP/sourcing sensor pushes current out to the load; the input module must pull that current to its internal common (0V) for the circuit to complete. Wiring it to a sourcing-only input leaves the circuit open and the input never switches.
Intermediate Work out a TON timer's output window

A TON timer has a 3.0s preset. The input goes true at t=0 and stays true until t=5.0s. At what time does the output turn ON, and for how long is it ON before the input drops?

Answer Output turns ON at t = 3.0s (when the preset elapses). It stays ON until the input drops at t = 5.0s, giving an ON duration of 5.0 − 3.0 = 2.0s.
Intermediate Identify the contact types in a seal-in circuit

In a standard Start/Stop/seal-in motor circuit, what contact type (NO or NC) is used for the Stop button, and why not the opposite?

Answer The Stop button is wired normally-closed (NC). Pressing it breaks the circuit, de-energizing the motor. If it were wired NO instead, a cut or disconnected Stop-button wire would make the button appear permanently "not pressed" — silently disabling the ability to stop the motor, which is exactly backwards for a safety-relevant control.
Advanced Scale a raw analog reading to engineering units

An analog input card reports a raw value of 16000 on its normalized 0–27648 scale. The input is calibrated to represent a tank level of 0–500 litres. What's the scaled value?

Answer value = 0 + (16000−0)/(27648−0) × (500−0) = 0.5788 × 500 ≈ 289.35 L. Confirm it in the scaling calculator above.
Advanced Map a PLC command onto a Modbus write

A PLC configured as a Modbus RTU master needs to switch ON relay 2 of a slave device at address 02. Referring back to the Modbus tutorial's function code reference, which function code accomplishes a single-coil write, and what would the frame's function code byte be?

Answer Function code 0x05 (Write Single Coil). The frame would begin 02 05 00 02 … — slave address 02, function 05, coil address 0x0002 (relay 2), followed by the ON value and a CRC-16 — exactly the pattern used throughout the Modbus tutorial's worked examples.
